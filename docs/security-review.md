## Validation

- The Admin panel change was reviewed for authorization, CSRF, provider changes, secret handling, input bounds, log disclosure, and accessible form controls. Its server actions require an administrator session, a current local password for OIDC, and reject demo mode. The OIDC secret is AES-256-GCM encrypted with a key derived from `AUTH_SECRET`, never returned to the browser, and saved in an owner-only file. A new secret is mandatory when the issuer or client ID changes; changing an issuer with linked accounts and disabling OIDC while passwordless linked accounts remain are blocked. A damaged saved configuration disables OIDC at startup instead of restoring the environment provider. The active provider remains fixed until restart, while the log threshold changes immediately.
- Generic OIDC uses an `oidc` callback and standard discovery. Existing Authentik environment configuration keeps its `authentik` callback until an administrator opts into the generic setup. New links save the provider issuer with the subject; old links are accepted only for the legacy issuer, which is retained on the first in-app save. Self-linking still requires a matching verified email claim.
- A disposable local administrator signed in, navigated both Settings tabs by keyboard, and saved a log level. The tab panels, labels, focus behavior, headings, and status message were checked in the browser. Axe returned no WCAG 2 A/AA, 2.1 AA, or 2.2 AA violations or incomplete checks on either Settings tab after contrast and touch-target fixes. This does not prove every screen or interaction meets WCAG 2.2 AA.
- Unit and security tests, TypeScript, lint, and production build cover the changed code.
- A local browser check covers local sign-in and the mandatory-email screen. Pa11y/axe found no issues on those screens. On the dashboard, axe marks five SVG chart labels for manual contrast review because it cannot determine the background behind the chart. The rendered labels use the foreground color; this is a tool limitation, not a measured contrast failure.
- A live local account with a mandatory email was linked to the existing Authentik identity after the account owner entered their local password. The saved account record had one matching email and a linked identity. After deploying image `habittrove-fork:7923877`, a fresh Authentik sign-in reached that account's dashboard with its existing habits and coin balance. The Unraid container was healthy and returned HTTP 200 locally, and its saved template points to the deployed image. The prior image and account backup were retained for rollback.
- This live check covers one existing account and one Authentik sign-in. It does not establish behavior for every identity-provider failure or future multi-user migration.

## Remaining risks

- An administrator can configure an OIDC issuer on an internal HTTPS address; Auth.js will contact its discovery endpoint. Restrict administrator access and treat the issuer as trusted infrastructure. Rotating or losing `AUTH_SECRET` makes an in-app saved client secret unreadable; keep a secure backup and restore the original secret or reconfigure OIDC. A malformed admin-config file requires host-side repair or removal while the app is stopped.
- Directly changing a provider issuer through container environment values bypasses the in-app linked-account guard. Keep the issuer stable for linked accounts, or unlink them first. Register `/api/auth/callback/oidc` with the provider before switching from legacy Authentik settings to the generic setup.
- A provider may issue pairwise subjects that change with the client ID. If the client ID changes, linked users may need to sign in locally and relink; keep a working local administrator recovery path.
- The log-level selector filters HabitTrove's server backup, scheduler, and data-action logs only. Auth.js, Next.js, browser logging, and container log retention are managed separately. Error objects may still contain operational details; restrict access to container logs.
- Use one application process per data directory. JSON writes and failed-login throttling are serialized only inside one process; multiple replicas can race or bypass the throttle. A transactional store and shared rate limiter are needed before scaling out.
- Habit completion is self-reported. An authorized member can still enter false past completions, one at a time, and receive rewards. Limiting edits to the past year reduces bulk abuse but cannot prove real-world activity.
- Files created by previous versions may have broad permissions. Restrict `data` and `backups` on the host before deployment. New files are owner-only.
- The initial email entered for a local account is not verified by email. Automatic Authentik linking requires a current local password and a matching Authentik email claim marked verified by the identity provider.
- Some new security UI strings use English fallback in non-English locales. Complete translations before treating those locales as fully localized.
- The development dependency audit still reports moderate advisories in old lint-tool dependencies. The production dependency audit reports none; a compatible lint-tool upgrade remains to be evaluated.
